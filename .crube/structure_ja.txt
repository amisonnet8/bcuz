.claude/	リポジトリで共有する Claude Code の設定
	hooks/	Claude Code が道具の前後に動かすフック

		crube-usage.md	crube の使い方：MCP と CLI、場所の探し方、両方の言語の説明の保ち方
		datetime.md	日時の扱い：UTC で持ち、表示だけ利用者のタイムゾーンに直す
		directory-structure.md	ファイルの置き場所と、リポジトリの構成
		distribution.md	配布方法：go install、goreleaser での配布物の作り方、リリースの流れ、cgo なし、バージョン
		documentation.md	ドキュメントの書き方：docs/ が正本、英語が先で日本語を対にする
		go-code.md	bcuz 固有の Go の決まり：引数、実行とシグナル、記録の書き方・読み方
		mtqg-usage.md	mtqg でメモ・todo・質問・不具合・決まり事を記録する方法
		naming.md	命名規則：製品名、用語の日本語と英語、JSON のフィールド、メッセージ、Go の名前
		qsoku-usage.md	ビルド・テスト・lint の qsoku の名前と呼び方
		srwr-usage.md	ファイルは srwr だけで変える（厳格モード）こと、テープの閉じ方
		testing.md	テスト方針と、サンドボックス・OS ごとの CI の落とし穴
		working-with-human.md	人間への頼み方：小さなつまずき、確認、見え方の了承
	settings.json	Claude Code の許可・サンドボックス・フック（人間が管理する）
	skills/	Claude Code のスキル
		commit-with-tape/	スキル：srwr のテープを閉じてコミットする
			SKILL.md	スキルの手順
		mutation-check/	スキル：実装をわざと壊して、テストが気づくか確かめる
			SKILL.md	スキルの手順
			spec.txt	プロジェクトの仕様の約束を1つずつ壊す変異の一覧（仕様の言葉で書く。最初は空）
			mutants/	変異を入れてテストを回す道具（独立した Go モジュール）
				go.mod	モジュールの定義（このプロジェクトとは別）
				main.go	構文の変異、または一覧の変異を1つずつ入れ、ファイルを元に戻す
				main_test.go	道具のテスト

internal/	bcuz のパッケージ（モジュールの外からは import できない）
	cli/	引数を読み、メッセージを出し、終了コードを決め、各機能を呼ぶ
		cli.go	Main：引数、コマンドの実行と記録、-H、--init、--version
		cli_test.go	オプション・--init・--version のテスト
		completion.go	--completion：埋め込んだシェルの補完スクリプトを出す
		completion_test.go	補完スクリプトをそれぞれ本物のシェルで動かす（入っていなければ飛ばす）
		completions/	補完スクリプト。bcuz に埋め込む決まった文
			bcuz.bash	bash：理由の後ろは bash-completion の _command_offset
			bcuz.fish	fish：理由の後ろは complete -C
			bcuz.ps1	PowerShell：理由の後ろは CompleteInput
			bcuz.zsh	zsh：理由の後ろは _normal
		e2e_test.go	本物の bcuz の通しテスト。動かすコマンドはテストのバイナリ自身
		e2e_unix_test.go	シグナルと Ctrl-C の通しテスト（Unix のみ）
		history_test.go	-H のテスト：表示、絞り込み、読めないとき
		messages.go	メッセージと使い方の文。docs/reference/cli.md と一字一句同じ
		version.go	--version が出す版（ビルドの情報から）
	docs/	テストだけ：docs/ と README.md が、本物の bcuz と、互いに合っているか
		cli_test.go	cli.md の使い方と --version のブロックが bcuz と一致する
		doc.go	パッケージのコメント
		examples_test.go	history-filter.md の各ブロックが、例の記録に対する -H の出力と一致する
		history_test.go	例の記録とすべての json ブロックが、文書の形式に合う
		links_test.go	相対リンクが存在し、docs/ が dev/ を指さない
		markdown_test.go	リポジトリの Markdown を読む補助
		transcript_unix_test.go	例と README の書き起こしを本物の bcuz に通す（Unix のみ）
		translations_test.go	英語の文書ごとに、同じ構造の日本語の文書がある
	history/	history.jsonl を読んで見せる：日付の絞り込み、時間、引用
		history.go	Read・Filter・FormatLine
		history_test.go	時間・引用・日付・1行の表示のテスト（境界を含む）
	record/	記録の形式を持つ：1行、.bcuz/ の探索、追記、--init
		append.go	1件の記録を1回の Write で追記する
		append_test.go	追記のテスト（同時に多く書く場合も）
		init.go	Init：.bcuz/ と空の history.jsonl を作る
		record.go	Record 型、固定した項目の順、1行の JSON
		record_test.go	1行の読み書きのテスト（オフセット付きの古い行も）
		root.go	FindRoot と、作業場からの相対の dir
		root_test.go	.bcuz/ の探索・相対の dir・Init のテスト
	run/	シェルを通さずにコマンドを起動して待つ。記録のことは知らない
		run.go	Run：終了コード、126 と 127、開始時刻と時間
		run_test.go	終了コードと標準入出力のテスト。コマンドはテストのバイナリ自身
		run_unix_test.go	シグナルで終わったコマンドのテスト（Unix のみ）
		signal_unix.go	Unix のシグナル：SIGINT・SIGQUIT は捨て、SIGTERM・SIGHUP は転送する
		signal_windows.go	Windows のシグナル：割り込みを捨てる

tools/	プロジェクトを作るための道具（bcuz には組み込まれない）
	licenses/	配布物に入れる依存のライセンス文を集める
		| go run ./tools/licenses <dir> <main パッケージ>。goreleaser がビルドの前に動かす。ライセンスのファイルが無いモジュールがあれば失敗する。

		main_test.go	ライセンス文を集める処理のテスト。bcuz が組み込むものの一覧
