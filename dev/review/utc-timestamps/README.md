# `ts` を UTC で書く

## 何を変えるか、なぜか

- 人間の依頼：「データを UTC で持って、表示するときにタイムゾーン設定に合わせる」
- 記録の `ts` を、**UTC（末尾 `Z`）**で書く。今は、実行した環境のタイムゾーンのオフセット付き（`+09:00` など）
- 表示（`-H`）は変えない。すでに、見る側のタイムゾーン（`TZ`・OS の設定）に直して表示し、日付の絞り込みも同じタイムゾーンで比べている
- 書式（`YYYY-MM-DD HH:MM:SS`）はロケールに合わせない（人間の回答：「表示はロケール設定で」はタイムゾーンのこと）

## 変更前後の例

同じ実行（日本で 2026-10-12 06:35:12 に始めた）の記録：

変更前：

```json
{"v":1,"ts":"2026-10-12T06:35:12.345+09:00","why":"run the tests","cmd":["make","test"],"dir":".","exit":0,"ms":8312}
```

変更後：

```json
{"v":1,"ts":"2026-10-11T21:35:12.345Z","why":"run the tests","cmd":["make","test"],"dir":".","exit":0,"ms":8312}
```

`bcuz -H` の表示は、どちらの記録でも同じ（見る側が日本なら）：

```
2026-10-12 06:35:12    0    8.3s  .  run the tests  $ make test
```

`TZ=UTC` で見ると：

```
2026-10-11 21:35:12    0    8.3s  .  run the tests  $ make test
```

## 決めること

- 古い記録（オフセット付き）は、書き換えない。読む側は、どちらの形も RFC 3339 として読む（`history.md` の互換性）。`v` は上げない（形式は同じで、書く値の選び方だけが変わる）
- 書く時刻の書式：`2006-01-02T15:04:05.000Z`（ミリ秒、UTC）
